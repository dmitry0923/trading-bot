# 23. Прямой пилот микроструктуры (L1) — SIM, forward сбор

## 1. Цель
Проверить гипотезу: предсказательный эффект OBI/microprice сосредоточен не в среднем по всем наблюдениям, а в хвостах |OBI| > k·σ. Замер на бесплатном дне (2024-10-01, CNYRUBF) показал:
- эффект 0,11–0,32 bps (средний по всем наблюдениям)
- круговые издержки 3–11 bps (спред 0,75–9,1 bps + комиссия 1,5 ₽/контракт/сторона + проскальзывание ~1 bp)
Вывод: средний эффект не окупает издержки. Хвосты — единственное правдоподобное объяснение возможной рентабельности.

## 2. Параметры запуска (SIM)
TRADING_MODE=SIMULATION
MICROSTRUCTURE_ENABLED=true
MICROSTRUCTURE_BUCKET_MS=1000
MICROSTRUCTURE_FLUSH_INTERVAL_MS=5000
MICROSTRUCTURE_MAX_QUEUE_SIZE=20000
Retention microstructure_snapshots: 90 дней (достаточно 4 недель).
Сбор идёт только по L1 (Quotations). Платный L2 не используется.

## 3. Сетка проверки (фиксируется ДО сбора, без подгонки)
Пороги по σ OBI внутри дня/сессии: k = 1.5, 2.0, 2.5, 3.0
Фильтр только эта сетка. Другие параметры не подбираются.

## 4. Критерии
Критерий успеха (must-pass):
- в хвосте |OBI| >= 2.0·σ условный edge (sign-of-OBI), после вычета круговых издержек >= 5 bps/сделку
- наблюдается >= 2 последовательных торговых недели подряд
- минимальный объём сбора >= 20 торговых дней

Критерий провала (stop rule):
- за 20 полных торговых дней ни по одному порогу из сетки не достигнут критерий успеха
- и хвост даёт edge < 5 bps (с учётом издержек)
Тогда гипотеза закрывается, покупка пилота не рекомендуется.

Правило зависания (hang detection):
- нет прироста строк в microstructure_snapshots > 30 минут подряд (при рабочем времени биржи МСК) — считать процесс зависшим (опрос каждые 10 минут). Автоперезапуск не делаем, только фиксация и ожидание ручного решения.

## 5. Метрики мониторинга
- alive (actuator/health/liveness), readiness (actuator/health)
- прирост строк microstructure_snapshots (total + прирост/час)
- microstructure.flush.rows/dropped/errors/skipped
- RSS (МБ), CPU %
- ошибки БД (критичны)
- последние 40–80 строк лога
