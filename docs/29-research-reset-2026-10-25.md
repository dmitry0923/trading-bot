## 1. Что аннулируется

Все **количественные результаты стратегий**, полученные бэктест-движком и его
обвязкой, независимо от того, упоминает ли конкретный артефакт затронутый код:

| Класс артефактов | Примеры | Причина |
|---|---|---|
| Таблицы доходности/PF/MDD/Sharpe | AGENTS.md «Калибровки», `18_10_2026.md`, PLAN-001 §5, docs/26 §6–§11, docs/27 | SL/TP и ликвидация не проверяются на баре входа (docs/28 №10); equity-кривая сдвинута (№11) |
| WFA/deployment-gate/holdout/MC | все `artifacts/*wfa*`, `*gate*`, `*holdout*`, `*robustness*` | те же + `BacktestRiskSimulator` (№12), funding-veto lookahead (№13) |
| Funding-veto / funding-window калибровки | пороги 9/2, 6/6, 5/8 | №13 (same-day vs prev-day), №14 (пропуски = 0) |
| Портфельный momentum + carry | docs/26 полностью | собственный движок, но валидировался теми же гейтами и сравнивался с тикерными прогонами; baseline обязан быть пересчитан заново |
| Pairs/FX relative value | docs/25, pairs-прогоны | №17 (beta lookahead), общая обвязка WFA |
| LLM-сигналы/veto | docs/17, docs/24, PF 0.71–1.11/1.771 | результаты были получены на том же движке; вывод «edge нет» должен быть подтверждён на исправленном движке, а не унаследован |
| Риск-сетка, max-hold, ORB, time-direction, session/pullback, ML | AGENTS research-разделы | тот же движок |

**Практическое следствие:** эти числа больше нельзя использовать для решений,
для сравнения новых прогонов или как «базу» в новых гипотезах. Они остаются в
документах только как исторические записи с пометкой **INVALID**.

## 2. Что НЕ аннулируется

- **Данные:** `candles`, `funding_history`, `cbr_rates_history`,
  `microstructure_snapshots` (forward L1) — это наблюдения, а не результаты стратегий.
- **Инфраструктура:** биржевые спеки, календарь, парсеры, репозитории, security-фиксы,
  сбор микроструктуры (наблюдательный слой).
- **Forward-факты:** например, «в выходные Alor отдаёт последний стакан» — измерение
  источника, не стратегия.
- **Качественные выводы о механике** (например, «WS QuotesSubscribe не работает»)
  остаются, пока не опровергнуты прямым тестом.

## 3. Протокол перезапуска (обязательный)

1. **Сначала исправить движок**, а не подгонять цифры:
   - entry-bar SL/TP/liq check (флаг + тест);
   - equity-кривая: бар 0, без дубля последней метки;
   - `BacktestRiskSimulator`: сброс состояния, P&L один раз, `pointValue`;
   - funding point-in-time (veto = previous clearing или документированное правило);
   - пары: beta/z на `i-1`; защитные выходы — проскальзывание.
2. **Зафиксировать версию движка** (commit + `engineVersion`) и записать её в каждый
   артефакт прогона.
3. **Пересчитать baseline заново** (CNYRUBF 730д, live-риск maxC=1/Kelly) — это
   новая точка отсчёта. Старые числа не упоминаются как сравнение.
4. **Предрегистрировать протокол** нового исследования (docs/26 §11.8 — образец):
   гейты, выборка, holdout, запрет донастройки на holdout.
5. Публиковать только результаты с `engineVersion` = текущая и пройденными гейтами;
   иначе — `INVALID`/`INCONCLUSIVE`.
6. Любой новый найденный дефект, влияющий на P&L, снова запускает п.1–3 для
   затронутого класса (валидность не «наследуется»).

## 5. Что это меняет в текущей работе

- **Сбор данных не останавливается:** пилот микроструктуры (PID 16080) и
  донакачки candles/funding продолжаются — это вход для нового исследования.
- **Покрытие тестами до 90 %** продолжается: тесты — инструмент обнаружения
  дефектов; каждый новый подтверждённый P&L-дефект добавляется в §3 п.1.
- **Live-параметры не меняются** (maxC=1, Kelly, LIVE-guard CNYRUBF, daily-loss):
  отсутствие валидного edge — не причина включать что-то в LIVE.
- **Никаких выводов «старое всё равно примерно так»**: сравнение с INVALID-числами
  запрещено, пока не пересчитан baseline.
