Идти по лестнице снизу вверх нужно только после полного прохождения предыдущей ступени.

# Раздел А. Локальный запуск (тест на истории и «бумагах»)

## А1. Бэктест — проверка стратегии на старых данных

**Для не-айтишника это означает, что:** прежде чем доверять роботу хоть рубль, стоит спросить: «А принесла бы эта стратегия прибыль в прошлом?» Бэктест — это **машина времени**: робот прогоняет свою стратегию по старым данным (например, за прошедший год) и сообщает, что было бы, если бы он торговал тогда. Никаких реальных денег — только цифры.

> У нашего робота **нет отдельного скрипта `backtest.py`** (он написан на Java). Бэктест встроен в самого робота — это REST-«дверь» в его API.

### Что нужно сделать

1. Робот должен быть запущен (см. SETUP_GUIDE.md): `docker compose up -d`.
2. Дождитесь, пока робот скачает историю свечей (это происходит автоматически в первые минуты работы; в логах будет видно загрузку данных). Если свечей по тикеру ещё нет, бэктест честно скажет «данных мало».
3. Выполните бэктест по интересующей бумаге.

**Windows (PowerShell), вариант через curl:**
```powershell
curl.exe "http://localhost:8080/api/v1/backtest/SBER?days=365"
```

**Windows, вариант через PowerShell (аккуратный вывод):**
```powershell
(Invoke-RestMethod -Uri "http://localhost:8080/api/v1/backtest/SBER?days=365") | ConvertTo-Json -Depth 5
```

**Linux / Mac (bash):**
```bash
curl "http://localhost:8080/api/v1/backtest/SBER?days=365"
```

### Как читать ответ

Ответ — это «отчёт» робота. Значение каждого поля объяснено в таблице сразу под примером:

```json
{
  "ticker": "SBER",
  "totalReturn": 0.1234,
  "sharpeRatio": 1.41,
  "maxDrawdown": 0.081,
  "winRate": 0.5421,
  "profitFactor": 1.87,
  "totalTrades": 152,
  "equityCurve": [100000, 100320.5, 100150.2, 101005.7]
}
```

| Поле | Значение в примере | Простыми словами |
|---|---|---|
| `totalReturn` | `0.1234` | доходность за период: 0.1234 = +12.34% |
| `sharpeRatio` | `1.41` | «качество» доходности: выше 1.2 — хорошо |
| `maxDrawdown` | `0.081` | самая глубокая «яма»: 0.081 = −8.1% от пика |
| `winRate` | `0.5421` | доля прибыльных сделок: 0.5421 = 54.21% |
| `profitFactor` | `1.87` | прибыль/убытки: на 1 ₽ убытка пришлось 1.87 ₽ прибыли |
| `totalTrades` | `152` | сколько сделок за период |
| `equityCurve` | список чисел | график капитала после каждой свечи |

**Критерии «можно в прод»** (все четыре должны быть выполнены одновременно):

| Показатель | Порог | Простыми словами |
|---|---|---|
| `sharpeRatio` | больше 1.2 | прибыль стабильная, а не «повезло раз» |
| `maxDrawdown` | меньше 0.15 (15%) | в худший момент капитал не просел глубже 15% |
| `profitFactor` | больше 1.3 | зарабатывает больше, чем проигрывает |
| `totalTrades` | не меньше 100 | сделок достаточно, чтобы верить статистике |

Если ответ выглядит как все нули и `totalTrades: 0` — это не поломка: значит, по тикеру ещё мало исторических данных. Подождите, пока робот их накопит (или запустите его на несколько торговых дней).

> **Важная оговорка (её часто не задают, но нужно знать):** прибыльность на истории **не гарантирует** прибыль в будущем. Рынок меняется. Бэктест — это экзамен, а не обещание.

## А2. Режим «Песочница» (SIMULATION) — робот думает, что торгует

**Для не-айтишника это означает, что:** «Песочница» — это детская площадка: робот играет в торговлю с **виртуальным балансом**. Он открывает и закрывает позиции, считает прибыль и убытки, но биржа и брокер в этом не участвуют, и никакие реальные деньги не двигаются. Идеально для тренировки и проверки.

В роботе за «песочницу» отвечает значение **`TRADING_MODE=SIMULATION`** (англ. simulation — «симуляция»).

### Как переключить флаг

1. Откройте файл `.env` в папке проекта:
   ```powershell
   cd C:\Users\<Ваше_имя>\trading-bot
   notepad .env
   ```
2. Найдите строку:
   ```
   TRADING_MODE=SIMULATION
   ```
   Убедитесь, что там именно `SIMULATION`, а не `LIVE`. Это и есть «флаг песочницы».
3. Если меняли — сохраните файл и перезапустите робота:
   ```powershell
   docker compose up -d --force-recreate
   ```
4. Не забудьте разрешить открытие виртуальных позиций: в `.env` должно быть `MAX_OPEN_POS=1` (или больше). При `MAX_OPEN_POS=0` робот анализирует, но не открывает позиции даже в песочнице.

### Что делает робот в песочнице

- Робот **не обращается к брокеру Алор за реальными ордерами**: в `SIMULATION` он сам придумывает цены и «исполняет» сделки мгновенно.
- Позиции, стратегии, статистика **записываются в базу данных** — вы можете видеть их в веб-интерфейсе (http://localhost) и анализировать.
- Всё работает так же, как в реальности, — кроме одного: денег на самом деле нет.

> ⚠️ **Нюанс, о котором почти никто не спрашивает:** даже в режиме `SIMULATION` робот **открывает позиции внутри своей базы данных**, если `MAX_OPEN_POS > 0`. Для базы данных это «настоящие» записи. Если вы переключитесь в `LIVE`, эти виртуальные позиции не переедут на биржу — но не забудьте их очистить или закрыть, чтобы статистика была честной.

## А3. Как убедиться, что вы в песочнице

Способ 1 — по логам. При запуске робот печатает строку режима:
```powershell
docker compose logs app | Select-String "TRADING_MODE"
```
Вы должны увидеть `TRADING_MODE=SIMULATION`.

Способ 2 — по веб-интерфейсу. Откройте http://localhost и войдите. На странице настроек/статуса будет виден режим торговли.

Способ 3 — «стрельба холостыми». Если в логах вы видите строки вида `sim-market-<ticker>-<time>` или цены около 100.0 — это виртуальные данные, вы точно в песочнице.

> **Никогда не переходите к разделу Б, пока минимум неделю не проработали в песочнице.** Это правило из реального чек-листа автора робота.

# Раздел Б. Запуск на реальном счёте (LIVE)

> ⚠️ **Дальше идут реальные деньги.** Прочитайте предупреждение в README.md. Одна ошибка на этом этапе может стоить денег. Делайте всё медленно и по чек-листу.

**Для не-айтишника это означает, что:** мы снимаем с робота «детские рукавички». Теперь он будет отдавать приказы брокеру Алор, и брокер будет исполнять их реальными деньгами с вашего счёта. Чтобы не наделать бед, сначала — проверки, потом — включение.

## Б1. Чек-лист «Проверь перед включением»

Распечатайте (мысленно) и отметьте галочкой **каждый** пункт. Если хоть один не выполнен — не включайте.

### Баланс и деньги
- [ ] На брокерском счёте лежит **только та сумма**, потерю которой вы готовы пережить.
- [ ] Вы понимаете, сколько робот может потратить: посчитайте `max-position-rub` (по умолчанию 50 000 ₽) × `max-open-positions` (3) = до **150 000 ₽** в позициях. Это предел, но лучше держать запас сверху.
- [ ] На счёте достаточно средств для гарантийного обеспечения, если торгуете фьючерс `Si` (залог 15 000 ₽ за контракт, см. `instruments.go`).

### Лимиты робота (в `.env` / `application.yml`)
- [ ] `TRADING_MODE=LIVE` — переключено осознанно, не случайно.
- [ ] `MAX_OPEN_POS` = `1` (начинайте с одной позиции за цикл).
- [ ] `risk.max-daily-loss-rub` установлен (например, 2 000 ₽) — робот сам остановится при дневном убытке.
- [ ] `risk.max-open-positions` не больше 1–2.
- [ ] `leverage.max-leverage=1.0` (не торговать в долг на первых порах).
- [ ] `ALOR_TOKEN`, `ALOR_REFRESH_TOKEN`, `ALOR_PORTFOLIO` заполнены **правильными** значениями (проверьте ещё раз в кабинете Алора).
- [ ] Время торговли (`trading-hours-start: "10:00"`, `trading-hours-end: "18:30"`) соответствует вашей стратегии.

### Компьютер и связь
- [ ] Компьютер (или облачная машина) будет включён **всю торговую сессию**. Если робот уснёт вместе с ноутбуком — он пропустит и стопы, и профиты.
- [ ] Интернет стабильный. Отключите режим «энергосбережения» и «сон» на время сессии.
- [ ] **Выключите автообновление Windows** на время торговли (Параметры → Центр обновления Windows → пауза обновлений до 5 недель). Внезапная перезагрузка посреди торгового дня — это пропущенные стопы. Если вы используете облачную машину — этот пункт не актуален (см. раздел В).
- [ ] Docker Desktop запущен (зелёный индикатор).

### Проверка «боевой обвязки»
- [ ] Минимум **1 неделя** в режиме `SIMULATION` с открытием позиций (`MAX_OPEN_POS>0`) уже прошла.
- [ ] Бэктест по вашим тикерам хотя бы не провален (см. раздел А1).
- [ ] Вы знаете, как посмотреть логи (TROUBLESHOOTING.md) и как принудительно закрыть позиции (Б3).
- [ ] Вы один раз потренировались нажимать «Экстренную остановку» (Б3) в песочнице.

> **Зачем выключать автообновление Windows?** Обновления любят перезагружать компьютер в самый неподходящий момент. Для торгового робота неожиданная перезагрузка — как отключение электричества во время операции. Лучше перестраховаться. Плюс: обновление Docker может перезапустить контейнеры и разорвать связь с биржей.

## Б2. Команда для запуска в фоновом режиме

**Для не-айтишника это означает, что:** если запустить робота «в лоб», он умрёт, как только вы закроете окно. В фоновом режиме робот продолжает работать, даже когда вы закрываете терминал. Как это сделать — зависит от того, где работает робот.

### Вариант 1. Windows + Docker (рекомендуется для новичков)

Самая простая и надёжная команда — она уже «фоновая» по своей природе:
```powershell
docker compose up -d
```
Флаг `-d` = «detach» (отцепить). Робот и базы данных работают в фоне; закрывайте окно сколько угодно. Остановить — `docker compose down`. Смотреть логи — `docker compose logs -f app`.

> `-d` — это и есть «фоновый режим» на Windows. Никакой магии больше не нужно.

### Вариант 2. Windows + прямой запуск Java (для разработчиков)

Если вы запускаете робота без Docker, через `gradlew`, то отдельное окно терминала закрывать нельзя. Вместо этого используйте `Start-Process`:
```powershell
Start-Process -FilePath "cmd.exe" -ArgumentList "/c gradlew.bat bootRun > bot.log 2>&1" -WindowStyle Hidden
```
Робот работает в скрытом окне, а весь вывод пишется в файл `bot.log`. Логи читаются так:
```powershell
Get-Content bot.log -Tail 50
```

### Вариант 3. Linux / облачная машина — `nohup` или `tmux`

**Для не-айтишника это означает, что:**
- `nohup` (расшифровывается «no hang-up», «не вешай трубку») — команда, которая говорит системе: «запусти программу так, чтобы она не умирала, когда терминал закроется». Как сотрудник, который работает, даже когда вы вышли из офиса.
- `tmux` — это «виртуальная комната» внутри терминала. Вы заходите в комнату, запускаете робота, выходите из комнаты (Ctrl+B, затем D), а робот остаётся там работать. Потом можно снова «зайти в комнату» и посмотреть на него.

**Через `nohup`** (запуск сборки/приложения в фоне):
```bash
cd /opt/trading-bot
nohup ./gradlew bootRun > bot.log 2>&1 &
```
- `nohup ... &` — «запусти в фоне и не убивай»;
- `> bot.log 2>&1` — пиши весь вывод (и обычный, и ошибки) в файл `bot.log`;
- Проверить, что процесс жив: `ps aux | grep gradle` или `tail -f bot.log`.

**Через `tmux`** (если хотите видеть живой вывод):
```bash
sudo apt install -y tmux          # один раз
tmux new -s bot                   # создать комнату "bot"
./gradlew bootRun                 # внутри комнаты запустить робота
```
Выйти из комнаты, оставив её работать: нажмите `Ctrl+B`, затем `D`.
Вернуться в комнату: `tmux attach -t bot`. Убить комнату: `tmux kill-session -t bot`.

> **Совет:** если робот развёрнут через Docker (а так и надо — см. раздел В), `nohup`/`tmux` не нужны вовсе: `docker compose up -d` уже фоновый, а автозапуск при перезагрузке делает `systemd` (Шаг 7 раздела В).

## Б3. Быстрая остановка при форс-мажоре

**Для не-айтишника это означает, что:** вдруг пошло не так — цена падает, робот ведёт себя странно. Нужно быстро «выдернуть шнур». У нас три уровня.

**Уровень 1 (мягкий): остановить открытие новых позиций, не трогая открытые.**

Откройте веб-интерфейс (http://localhost) и нажмите «Выключить торговлю» (аналог `/api/v1/trading/disable`). Робот перестанет открывать новое, но продолжит следить за открытыми позициями и закроет их по стопам. Через API:
```powershell
$token = (Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/v1/auth/login" -ContentType "application/json" -Body '{"username":"admin","password":"<пароль>"}').accessToken
Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/v1/trading/disable" -Headers @{ Authorization = "Bearer $token" }
```

**Уровень 2 (срочный): закрыть все позиции прямо сейчас.**
```powershell
Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/v1/trading/force-close" -Headers @{ Authorization = "Bearer $token" }
```
Робот немедленно выставит ордера на закрытие всех открытых позиций.

**Уровень 3 (аварийный): остановить всё на компьютере.**
```powershell
docker compose down
```
Останавливаются робот, базы данных, всё. Открытые позиции **останутся** у брокера, но робот за ними больше не следит — закройте их вручную через терминал Алора, чтобы не «висеть» в рынке.

# Раздел В. Облако Yandex Cloud (для новичка)

**Для не-айтишника это означает, что:** чтобы робот торговал 24/7, ему нужен «неумирающий компьютер» — **виртуальная машина (ВМ)** в облаке Yandex. Это чужой сервер в Москве, который работает круглосуточно, пока вы спите. Вы снимаете его в аренду (плата — копейки в день), заселяете туда робота, и он работает без вашего участия. Ваш домашний ноутбук может быть выключен.

> **Зачем это нужно, если есть Docker на домашнем компьютере?** Потому что дома: ноутбук уснёт, интернет отключится, Windows перезагрузится. А облако живёт в дата-центре с бесперебойным питанием и стабильным интернетом. Для торговли это принципиально.

## Шаг 1. Регистрация и платёжный аккаунт

1. Зайдите на https://cloud.yandex.ru и нажмите «Войти» / «Попробовать бесплатно».
2. Войдите под Яндекс ID (или зарегистрируйтесь).
3. Создайте **платёжный аккаунт**:
   - Выберите «Физическое лицо» (для личных проектов) или «Юридическое лицо» (для бизнеса);
   - Привяжите банковскую карту (без неё ВМ не создаются — так работает аренда).
4. Пополните баланс. Для тестового запуска достаточно **100 ₽**:
   - в консоли облака: верхнее меню → «Баланс» → «Пополнить баланс» → введите `100` ₽ → оплатите картой.
   - Обычно есть и **пробный грант** (промокод на бонус) — если видите предложение, активируйте его: это почти бесплатный месяц аренды.

> **Почему карта обязательна?** Облако — это аренда чужих серверов. Аренда оплачивается заранее (с баланса), а карта нужна для пополнения. Если баланс закончится — машина просто остановится (никаких скрытых долгов, но робот, разумеется, встанет). Удобно выставить «уведомление при балансе ниже 100 ₽».

## Шаг 2. Создание виртуальной машины (ВМ)

**Для не-айтишника это означает, что:** мы «снимаем квартиру» в дата-центре: выбираем, насколько она большая, в каком доме (регионе) и с какими ключами от двери. Дальше система даёт нам адрес (IP) этой квартиры.

### Пошагово в консоли Yandex Cloud

1. В консоли выберите ваш каталог (он создаётся автоматически) → слева в меню **«Compute Cloud»** → **«Виртуальные машины»** → кнопка **«Создать ВМ»**.
2. **Имя**: `trading-bot`.
3. **Зона доступности**: выберите `ru-central1-a` (Москва). 
   > Почему Москва? Потому что биржа (Московская) и брокер (Алор) находятся физически в Москве. Чем ближе сервер — тем меньше «задержка» (пинг), тем быстрее робот получает котировки и отдаёт приказы. Задержка в торговле — это деньги.
4. **Образ**: выберите Ubuntu 22.04 LTS (предустановленная ОС).
5. **Платформа и конфигурация** — параметры арендуемого «железа»:
   - **Минимум для робота**: 2 vCPU (процессора) и 2 ГБ RAM (памяти). 
   - **Рекомендуем с запасом**: 2 vCPU / 4 ГБ RAM (как у автора проекта) — робот с базой и мониторингом комфортнее себя чувствует.
   - **Диск**: 30 ГБ (стандартный SSD). Этого хватит надолго.
6. **Публичный IP-адрес**: включите «Эфемерный» (бесплатный вариант; если ВМ пересоздаёте — адрес меняется, но для нас это некритично).
7. **Доступ по SSH**: переключатель «SSH-ключ». Сюда вставляется **публичная** часть вашего ключа (как её получить — Шаг 3; на этом экране вам понадобится открыть вторую вкладку).
8. Нажмите **«Создать ВМ»** и подождите 1–3 минуты. Появится машина с публичным адресом вида `84.201.100.200` — запишите его.

> **Сколько это стоит?** ВМ 2 vCPU / 4 ГБ в Москве стоит около 3–5 ₽/час, т.е. ~100–150 ₽/мес при простое и несколько сотен рублей в месяц при активной работе с диском и сетью. Пополненных 100 ₽ хватает на несколько дней теста; для постоянной работы закладывайте ~500 ₽/мес.

## Шаг 3. Подключение по SSH

**Для не-айтишника это означает, что:** SSH — это «секретная дверь» в вашу облачную машину. Открывается она не паролем, а **ключом** — как домофон: у вас в руках брелок (закрытый ключ), а в двери приёмник (открытый ключ). Приёмник вы отдали облаку при создании ВМ (Шаг 2), брелок хранится у вас. Ключи работают парой и только вместе.

> Важно понимать разницу:
> - **Закрытый (приватный) ключ** — ваш «брелок». **Никому и никогда его не показывайте** (это как чип от домофона — если скопируют, зайдут в вашу квартиру).
> - **Открытый (публичный) ключ** — «приёмник». Его можно смело вставлять в облако.

### 1. Сгенерируйте пару ключей (один раз, на своём компьютере)

**Windows (PowerShell):**
```powershell
ssh-keygen -t ed25519 -C "trading-bot"
```
На вопросы нажмите Enter (пустая парольная фраза — можно и без неё, но надёжнее задать). Появятся два файла:
- `C:\Users\<Ваше_имя>\.ssh\id_ed25519` — **закрытый** (никому не показывать);
- `C:\Users\<Ваше_имя>\.ssh\id_ed25519.pub` — **открытый** (вставляем в облако).

**Linux / Mac (bash):** та же команда `ssh-keygen -t ed25519 -C "trading-bot"`.

### 2. Посмотрите содержимое открытого ключа

**Windows (PowerShell):**
```powershell
Get-Content C:\Users\<Ваше_имя>\.ssh\id_ed25519.pub
```
**Linux/Mac:** `cat ~/.ssh/id_ed25519.pub`

Вы увидите одну длинную строку вида `ssh-ed25519 AAAAC3NzaC1... trading-bot`. Скопируйте её **целиком** и вставьте в поле «SSH-ключ» при создании ВМ (Шаг 2, п. 7). Если ВМ уже создана без ключа — пересоздайте её (проще, чем добавлять ключ потом).

### 3. Подключитесь

**Windows (PowerShell):** команда ниже выполняется **из домашней папки** (или укажите путь к ключу):
```powershell
ssh -i C:\Users\<Ваше_имя>\.ssh\id_ed25519 ubuntu@<IP-адрес-вашей-ВМ>
```
**Linux/Mac:**
```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@<IP-адрес-вашей-ВМ>
```

Если всё правильно — первый раз система спросит «Are you sure you want to continue connecting?» — ответьте `yes` (Enter). Вы окажетесь «внутри» машины: приглашение изменится на что-то вроде `ubuntu@trading-bot:~$`. Поздравляем — вы в облаке!

> **Проверка на память:** если Windows ругается «Permissions for ... are too open» — выполните:
> ```powershell
> icacls C:\Users\<Ваше_имя>\.ssh\id_ed25519 /inheritance:r /grant:r "$($env:USERNAME):R"
> ```
> Это уже сисадминский трюк, но он решает частую проблему.

## Шаг 4. Как закинуть код на ВМ

**Для не-айтишника это означает, что:** код живёт на вашем компьютере. Теперь его нужно «перевезти» в облако. Два способа — как переехать: коробками (scp) или по подписке (git). Выберите один.

### Способ 4.1. По коробкам — `scp` (быстрый однократный перенос)

`scp` — «копирование по SSH», как отправка папки по защищённому каналу.

**Windows (PowerShell), из родительской папки проекта:**
```powershell
scp -r C:\Users\<Ваше_имя>\trading-bot ubuntu@<IP-адрес>:/home/ubuntu/
```
**Linux/Mac (bash):**
```bash
scp -r ~/trading-bot ubuntu@<IP-адрес>:/home/ubuntu/
```

На ВМ код окажется в `/home/ubuntu/trading-bot`. Проверьте:
```bash
ssh ubuntu@<IP-адрес> "ls /home/ubuntu/trading-bot"
```

> **Минус способа:** обновления придётся заливать заново. Если ваш репозиторий **публичный** на GitHub, удобнее способ 4.2.

### Способ 4.2. По подписке — `git clone` (рекомендуется)

Если проект лежит в GitHub, на ВМ его можно скачать напрямую. На ВМ (в SSH-сессии):
```bash
cd /opt
sudo mkdir -p trading-bot && sudo chown ubuntu:ubuntu trading-bot
cd trading-bot
git clone https://github.com/<ваш-логин>/trading-bot.git .
```
> Точка в конце `git clone ... .` означает «склонировать в текущую папку». Обновления — `git pull` внутри `/opt/trading-bot`.

**Почему `/opt`?** Это стандартная папка Linux для «установленных» программ. Можете использовать `/home/ubuntu/trading-bot` — разницы для робота нет, но `/opt` выглядит солиднее и не засоряет домашнюю папку.

## Шаг 5. Установка Docker на ВМ

**Для не-айтишника это означает, что:** раньше Docker был у вас на компьютере. Теперь он нужен и на облачной машине — это «коробки», в которых живёт робот.

Подключитесь по SSH (Шаг 3) и выполните **по одной** команде:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
```

Проверка:
```bash
docker --version
docker compose version
```
Если обе команды показали версии — Docker готов.

> Если у вас свежая Ubuntu, команды могут попросить пароль — это нормально, пароль пользователя `ubuntu` (или тот, что задали при создании ВМ).

## Шаг 6. Запуск робота на ВМ в режиме теста (24/7)

**Для не-айтишника это означает, что:** мы заселяем робота в облачную «квартиру» и включаем ему режим «песочница», чтобы он **виртуально** торговал круглосуточно, пока ваш домашний компьютер выключен.

1. **Перейдите в папку с кодом** (в SSH-сессии):
   ```bash
   cd /opt/trading-bot
   ```

2. **Создайте файл `.env`** — как в SETUP_GUIDE.md, но на ВМ. Откройте редактор:
   ```bash
   nano .env
   ```
   Вставьте (правой кнопкой мыши в терминале = вставить) минимальный безопасный набор:
   ```dotenv
   DB_PASS=<надёжный-пароль-для-базы>
   TRADING_MODE=SIMULATION
   MAX_OPEN_POS=1
   AUTH_USER=admin
   AUTH_PASSWORD=<надёжный-пароль-для-интерфейса>
   JWT_SECRET=<сгенерируйте-строку-командой-ниже>
   METRICS_SCRAPE_TOKEN=<сгенерируйте-вторую-строку>
   GRAFANA_ADMIN_PASSWORD=<надёжный-пароль-для-графиков>
   LLM_PROVIDER=ROUTER_AI
   LLM_API_KEY=<ваш-ключ-routerai>
   ```
   Сгенерировать случайные строки прямо на ВМ:
   ```bash
   openssl rand -base64 48
   ```
   Сохранить и выйти из `nano`: `Ctrl+O`, Enter, `Ctrl+X`.

3. **Запустите робота** в фоне:
   ```bash
   docker compose up -d
   ```
   Первый раз будет долго (скачаются образы и соберётся робот) — это нормально.

4. **Проверьте, что всё живо:**
   ```bash
   docker compose ps
   curl http://localhost:8080/actuator/health
   ```
   Ответ `{"status":"UP"}` = робот работает. Теперь он крутится в облаке **непрерывно**, даже когда вы закрыли ноутбук.

5. **Посмотрите логи** (главная привычка оператора):
   ```bash
   docker compose logs -f app
   ```
   Выход из просмотра — `Ctrl+C`.

> **Почему это «тест»?** Потому что `TRADING_MODE=SIMULATION`: робот «торгует» виртуально, но при этом живёт в правильном окружении (стабильный интернет, круглосуточная работа) — то есть проходит полную проверку того самого окружения, в котором будет работать с реальными деньгами. Проведите так минимум неделю, потом (осознанно, по чек-листу раздела Б) поменяйте в `/opt/trading-bot/.env`:
> ```
> TRADING_MODE=LIVE
> ALOR_TOKEN=...
> ALOR_REFRESH_TOKEN=...
> ALOR_PORTFOLIO=D12345
> ```
> и перезапустите: `docker compose up -d --force-recreate`.

## Шаг 7. Автозапуск через systemd

**Для не-айтишника это означает, что:** облако иногда перезагружается (плановая профилактика, обновления). После перезагрузки Docker-контейнеры сами **не** поднимутся — робот просто замолчит, а вы даже не узнаете. `systemd` — это «диспетчер облака», который умеет сам запускать программы при старте системы. Мы научим его будить робота.

### 7.1. Создайте сервис (инструкцию для диспетчера)

В SSH-сессии выполните по одной команде:

```bash
sudo tee /etc/systemd/system/trading-bot.service > /dev/null <<'EOF'
[Unit]
Description=MMVB Trading Bot
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/trading-bot
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
```

Разберём, что здесь написано (для не-айтишника):
- `WorkingDirectory=/opt/trading-bot` — «работать из этой папки» (там лежат код и `.env`);
- `ExecStart=/usr/bin/docker compose up -d` — «при старте системы поднять робота»;
- `ExecStop=/usr/bin/docker compose down` — «при остановке аккуратно погасить»;
- `Restart=on-failure` — «если упал с ошибкой — попробуй ещё раз»;
- `After=docker.service` / `Requires=docker.service` — «начинать только после того, как проснулся сам Docker».

> Если `docker` установлен не в `/usr/bin/docker`, проверьте путь: `which docker` и замените в файле (редко нужно).

### 7.2. Включите автозапуск

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now trading-bot
```
- `enable` — «включить автозапуск при загрузке системы»;
- `--now` — «и запусти прямо сейчас».

### 7.3. Проверьте статус

```bash
systemctl status trading-bot
```
Красивая зелёная надпись `active (exited)` означает «сервис сработал, контейнеры подняты». Проверьте сам робот:
```bash
curl http://localhost:8080/actuator/health
```

### 7.4. Проверка «на прочность» (рекомендуется)

Перезагрузите машину и посмотрите, оживёт ли робот сам:
```bash
sudo reboot
```
Через минуту зайдите заново по SSH и проверьте:
```bash
curl http://localhost:8080/actuator/health
docker compose ps
```
Если `UP` — автозапуск работает, робот переживает перезагрузки облака без вашего участия.

> **Полезные команды на будущее:**
> - Остановить сервис и контейнеры: `sudo systemctl stop trading-bot`
> - Запустить снова: `sudo systemctl start trading-bot`
> - Отключить автозапуск совсем: `sudo systemctl disable trading-bot`
> - Посмотреть логи сервиса: `journalctl -u trading-bot -f`
