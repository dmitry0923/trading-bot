# Предрегистрация: календарь и overnight-эффекты на акциях TQBR 2018–2026 (2026-11-02)

**Статус:** зафиксировано **ДО** прогона. После получения чисел параметры не
меняются; изменение любого пункта = новый протокол и новый OOS.

**Зачем:** intraday ORB на акциях отклонён (`docs/51`: dev PF 0,780, 0/3
фолдов). Следующий независимый класс — **календарные и overnight-эффекты**
на длинной дневной истории: turn-of-month, pre-holiday, overnight drift и
overnight-реверсия после down-дня. Это не тренд, не фильтр и не
микроструктура; данные — 8,8 года DAY_1 по 8 акциям TQBR.

> Это **pre-screen вне движка** (как `docs/36`/`docs/51`): симулятор
> повторяет исполнительные допущения (close→next open, close→close,
> комиссия, slippage), но не является formal-вердиктом. PASS означает
> только «реализовать в движке и прогнать `docs/30` §4–§6».

## 1. Данные и период

| Параметр | Значение |
|---|---|
| Инструменты | `GAZP, LKOH, MGNT, NVTK, PLZL, ROSN, SBER, TATN` (8 акций TQBR) |
| ТФ | `DAY_1`, 2018-01-03…2026-10-30 |
| Торговые дни | только **будни** (weekend-сессии исключены) |
| Фильтр | день должен иметь OHLC-бар; для TOM — ≥ 3 бара в месяце и следующем месяце |
| Издержки (база) | комиссия **0,05 %/сторона** + slippage **1 bp/сторона** |
| Издержки (stress) | комиссия **0,10 %/сторона** + slippage **3 bp/сторона** |
| Размер | **100 000 ₽ notional** на сделку, целые акции, long-only |
| Funding/дивиденды | не моделируются (акции) |

**Разделение:** dev = первые **70 %** уникальных торговых дней (≈ 1 650,
2018–2022), OOS = последние **30 %** (≈ 700, 2023–2026). Граница — по
календарю, а не по числу сделок. OOS запускается один раз.

**Оговорка о данных:** период 2019–2026 по этим акциям использовался в
`docs/43` для **другой** гипотезы (momentum+low-vol, full-period, REJECTED);
формального OOS-сплита там не было. Здесь OOS 2023–2026 впервые используется
для календарной гипотезы. Дивидендные отсечки не корректируются: для
long-only это **консервативный bias** (цена падает на ex-date, дивиденд не
начисляется).

## 2. Варианты (ровно 4, без сетки)

Все варианты — **только LONG**, одна позиция на инструмент в событии.

| ID | Название | Вход | Выход | Событие |
|---|---|---|---|---|
| **K1** | `tom_long` | close за 3-й торговый день до конца месяца M | close 3-го торгового дня месяца M+1 | turn-of-month: последние 2 дня M + первые 3 дня M+1 |
| **K2** | `overnight_long` | close каждого торгового дня | open следующего торгового дня | overnight drift, каждый день |
| **K3** | `overnight_after_down` | close дня, если `close < open` | open следующего торгового дня | overnight-реверсия после down-дня |
| **K4** | `pre_holiday_long` | close предыдущего торгового дня | close последнего дня перед праздником | pre-holiday: следующий торговый день отделён ≥ 1 **будним** нерабочим днём |

**Праздник** определяется по календарю торгов: если между двумя соседними
торговыми днями есть хотя бы один будний день без бара, то второй день —
post-holiday, а первый — pre-holiday. Обычный weekend (пт→пн) праздником не
считается. Это автоматически ловит переносы и мостовые дни.

**Пропуски:** нет предыдущего/следующего бара, < 3 баров в месяце, нет цены
входа/выхода — событие пропускается.

## 3. Метрики

- pooled по 8 инструментам: net, PF, win rate, средний/медианный net;
- распределение по тикеру, варианту, hold (дни);
- MDD по кумулятивному net (в ₽ и % от 100k);
- **date-block bootstrap** (2 000 итераций, seed 42) по датам выхода;
- dev/OOS-consistency — 3 равных временных фолда.

## 4. Гейты

### 4.1 Dev (выбор не более одного варианта)

| # | Гейт | Порог |
|---|---|---|
| D1 | Сделок (pooled) | **≥ 100** |
| D2 | Profit Factor | **≥ 1,30** |
| D3 | P(noEdge), date-block bootstrap | **< 0,05** |
| D4 | Средний net | **> 0** |
| D5 | Dev-consistency (3 фолда) | **≥ 0,60** |

Если D1–D5 проходят несколько вариантов — выбирается **максимальный PF**,
без дополнительной настройки. Если ни один не проходит — `REJECTED_DEV`,
OOS не оценивается.

### 4.2 OOS (один прогон выбранного варианта)

| # | Гейт | Порог |
|---|---|---|
| O1 | Сделок | **≥ 100** |
| O2 | Profit Factor | **≥ 1,30** |
| O3 | P(noEdge) | **< 0,05** |
| O4 | CI95 среднего net (date-block) | **не содержит 0** |
| O5 | Max Drawdown | **≤ 40 %** от 100k |
| O6 | OOS-consistency (3 фолда) | **≥ 0,60** |
| O7 | Stress PF (0,10 %/сторона + 3 bp) | **≥ 1,15** |

**Правило вердикта:** `PASS_PRECHECK` — O1–O7 все; `REJECTED` — O2 или O5
провалены, либо Stress PF < 1,15; `INCONCLUSIVE` — O2/O5/stress пройдены,
но O1/O3/O4/O6 нет.

PASS не является live-допуском: дальше — реализация **того же** варианта в
движке и formal WFA (`docs/30` §4–§6), затем `deployment-gate`.

## 5. Анти-подбор

1. Ровно 4 варианта, параметры зафиксированы. Сетки нет.
2. Никакого выбора «лучшей акции»: вердикт — только по **pooled** выборке;
   разбивка по тикерам — диагностика.
3. OOS 2023–2026 запускается **один раз**.
4. Отрицательный результат закрывает класс календарь/overnight на акциях
   TQBR на этом окне; повторные окна/пороги запрещены.
5. Stress-издержки не подбираются.

Прогон: 2026-11-02, `scripts/research_equity_calendar_overnight.ps1`,
`artifacts/equity_calendar_overnight_2026-11-02_summary.json` (+ dev/oos CSV).
8 акций, **2 215** будних торговых дней. Фактическая граница по правилу 70 %:
dev = **1 550** дней (2018-01-03…2024-03-21), OOS = **665** дней
(2024-03-22…2026-10-30); оценка в §1 была приблизительной, правило не
менялось.

**O7 ❌** (stress PF 0,613 < 1,15); O3/O4/O6 также не пройдены. K1 выбран
на dev по максимальному PF среди кандидатов, но OOS развернул его в минус.

### 7.4 Интерпретация

1. **Turn-of-month на акциях — режимный эффект, а не устойчивый edge.**
   В dev 2018–2024 он давал +752,60 ₽ на 100k за 7,6-дневное удержание
   (PF 1,55, все 3 фолда положительны), в OOS 2024–2026 — −597,74 ₽
   (PF 0,673). Это тот же паттерн, что у momentum+low-vol: результат
   держится на историческом сегменте и исчезает на свежем.
2. **Overnight-эффекта нет после издержек.** K2 (каждый день) PF 0,710,
   K3 (после down-дня) PF 0,570 — средний overnight-возврат не покрывает
   12 bps round trip. Это согласуется с тем, что ORB на акциях тоже
   отрицателен: intraday/overnight движения не дают направленного
   преимущества на этом окне.
3. **Pre-holiday — единственный «пограничный» вариант** (PF 1,64 на dev,
   376 сделок), но p=0,060 не прошёл D3, поэтому OOS для него не
   запускался. Это не подтверждение и не опровержение — insufficient
   evidence по заранее заданному порогу.
4. **Класс закрыт на 2018–2026.** OOS 2024–2026 израсходован для
   календарной гипотезы; повторные окна/пороги на нём запрещены.
5. **Оговорка:** long-only и без дивидендов — консервативный bias, но он
   не спасает OOS; на dev K1 был бы ещё выше с дивидендами, что усиливает
   вывод о режимности, а не об устойчивости.
6. **Методический урок:** dev-гейт должен требовать **CI95 low > 0**, а не
   только p < 0,05. K1 прошёл D3 (p=0,043), но его dev-CI95
   [−120,64; +1568,16] содержал ноль — сигнал не был статистически
   устойчивым уже на dev. В будущих протоколах это условие добавляется в
   dev-гейты; текущий прогон не пересматривается.
