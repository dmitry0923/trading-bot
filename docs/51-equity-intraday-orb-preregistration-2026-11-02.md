# Предрегистрация: intraday ORB на акциях TQBR (2026-11-02)

**Статус:** зафиксировано **ДО** прогона. После получения чисел параметры не
меняются; изменение любого пункта = новый протокол и новый OOS.

**Зачем:** capacity audit (`docs/35` §1.1.1) показал, что baseline даёт 82
сделки за 730д, а для цели 100 %/год нужен профиль **≥ 500–1 000 сделок**
при захвате 20–40 % дневного диапазона. ORB на CNYRUBF этот профиль по
частоте дал (363 сделки на dev), но OOS его отверг (`docs/36`). На акциях
TQBR ORB **не проверялся**: там другой микроструктурный класс (утренний
аукцион, гэпы, секторные потоки), а истории 2 года MINUTE_10 достаточно для
~4 500 instrument-days и тысяч сделок.

> Это **pre-screen вне движка** (как `docs/36`): симулятор повторяет
> исполнительные допущения движка (сигнал на закрытии бара `i`, fill на
> `open` `i+1`), но не является formal-вердиктом. PASS означает только
> «реализовать в движке и прогнать `docs/30` §4–§6».

## 1. Данные и период

| Параметр | Значение |
|---|---|
| Инструменты | `GAZP, LKOH, MGNT, NVTK, PLZL, ROSN, SBER, TATN, VTBR` (9 акций TQBR) |
| ТФ | `MINUTE_10`, 2024-10-24…2026-10-31 |
| Торговые дни | только **будни** (weekend-сессии исключены: тонкая ликвидность) |
| Фильтр дня | ≥ 5 баров MINUTE_10 |
| Издержки (база) | комиссия **0,05 %/сторона** + slippage **1 bp/сторона** (как `docs/43`) |
| Издержки (stress) | комиссия **0,10 %/сторона** + slippage **3 bp/сторона** |
| Размер | **100 000 ₽ notional** на сделку, целые акции, без плеча |
| Funding | нет (акции) |

**Разделение:** dev = первые **70 %** уникальных торговых дней, OOS =
последние **30 %**. Граница — по календарю, а не по числу сделок. OOS
запускается один раз и не используется для выбора варианта.

**Нормировка 100k:** это исследовательская база для сравнимости P&L между
акциями с разной ценой, а не live-сайзинг. Масштабирование/маржа — отдельный
шаг после PASS.

## 2. Стратегия (ровно один вариант, без сетки)

**E1 `orb30_close`** — та же замороженная логика, что H1 в `docs/36`:

- Opening range = high/low баров **10:00–10:30** (3 бара MINUTE_10).
- Первый бар после 10:30, пробивший `high` диапазона → **LONG**;
  пробивший `low` → **SHORT**.
- Если в одном баре задеты оба уровня → день пропускается.
- Вход — по `open` следующего бара после сигнала.
- Выход — по `close` последнего бара дня.
- SL/TP нет.
- Не более одной сделки в день на инструмент.

**Пропуски:** < 2 баров в OR-окне, нет бара после 10:30, нет следующего бара
для входа, `OR range <= 0`.

## 3. Метрики

- pooled по 9 инструментам: net, PF, win rate, средний/медианный net, σ;
- captured range = `|exit − entry| / dayRange` (абсолютный захват) и
  `net / gross` (направленный edge);
- распределение по тикеру, направлению, hold;
- MDD по кумулятивному net (в ₽ и % от 100k);
- **date-block bootstrap** (2 000 итераций, seed 42): resampling по датам
  выхода, а не по отдельным сделкам — иначе 9 одновременных сделок в один
  день считались бы независимыми.

## 4. Гейты

### 4.1 Dev (решение о запуске OOS)

| # | Гейт | Порог |
|---|---|---|
| D1 | Сделок (pooled) | **≥ 200** |
| D2 | Profit Factor | **≥ 1,30** |
| D3 | P(noEdge), date-block bootstrap | **< 0,05** |
| D4 | Средний net | **> 0** |
| D5 | Dev-consistency (3 равных временных фолда) | **≥ 0,60** |

Если D1–D5 не проходят — `REJECTED_DEV`, OOS **не оценивается**.

### 4.2 OOS (один прогон)

| # | Гейт | Порог |
|---|---|---|
| O1 | Сделок (pooled) | **≥ 100** |
| O2 | Profit Factor | **≥ 1,30** |
| O3 | P(noEdge) | **< 0,05** |
| O4 | CI95 среднего net (date-block) | **не содержит 0** |
| O5 | Max Drawdown | **≤ 40 %** от 100k |
| O6 | OOS-consistency (3 равных фолда) | **≥ 0,60** |
| O7 | Stress PF (0,10 %/сторона + 3 bp) | **≥ 1,15** |

**Правило вердикта:**

- `PASS_PRECHECK` — O1–O7 все;
- `REJECTED` — O2 или O5 провалены, либо Stress PF < 1,15;
- `INCONCLUSIVE` — O2/O5/stress пройдены, но O1/O3/O4/O6 нет.

PASS не является live-допуском: дальше — реализация **того же** варианта в
движке и formal WFA (`docs/30` §4–§6), затем `deployment-gate`.

## 5. Анти-подбор

1. Один вариант, один OR-порог (10:00–10:30), один выход (close дня).
   Сетки нет.
2. Никакого выбора «лучшей акции»: вердикт — только по **pooled** выборке;
   разбивка по тикерам — диагностика, не основание для PASS.
3. OOS 2024-10…2026-10 запускается **один раз**.
4. Отрицательный результат закрывает класс intraday ORB на акциях TQBR на
   этом окне; повторные пороги/окна на нём запрещены.
5. Stress-издержки не подбираются: 0,10 %/сторона + 3 bp зафиксированы
   заранее.

### 7.3 Интерпретация

1. **Сигнал ORB на акциях не имеет направленного edge**: средний net
   −150,89 ₽ на 100k, при издержках ~120 ₽/сделку (0,05 %/сторона + 1 bp
   round trip). Даже **до** издержек средний gross ≈ −30 ₽ — пробой
   10:00–10:30 не предсказывает направление до закрытия дня; захват 38,9 %
   диапазона — это абсолютное движение (и winners, и losers), а не
   преимущество (направленный edge −46 %).
2. **Эффект не режимный, а структурный**: все три временных фолда
   отрицательны, 8 из 9 тикеров отрицательны. Это не «один плохой квартал»
   и не «одна плохая акция».
3. **Класс ORB закрыт на двух вселенных**: CNYRUBF (`docs/36`, OOS PF 1,028
   → REJECTED) и акции TQBR (dev PF 0,780 → REJECTED_DEV). Повторные
   OR-окна/пороги на этом окне запрещены; «fade ORB» — отдельная гипотеза,
   которую нельзя проверять на том же dev-окне без нового протокола.
4. **Урок для capacity:** частота 3 257 сделок за ~1,8 года достигнута, но
   знак edge отрицательный. Частота сама по себе не создаёт прибыль —
   подтверждение вывода `docs/35` §1.1.1: нужен захват с направленным
   преимуществом, а не просто много сделок.
