## 4. Что это значит для текущих результатов

- P0 №7/№8 относятся к **live/SIM исполнению**, не к research: после фикса
  неисполненный лимитный вход больше не становится «открытой позицией», а pending
  вход связывается с outbox и разрешается реконсилятором.
- P1 №6 меняет сайзинг акций только там, где SL отличается от 2% (сетка
  `stockGrid`); результаты с SL=2% не изменились.
- P2 №5 меняет комиссию только при **дробном** `commissionMultiplier`
  (стресс-прогоны MC с 2/3/5 не затронуты).
- Дефекты §2 (особенно №10, №12, №13) — это ограничения **сопоставимости**
  уже опубликованных бэктестов. Их нельзя править молча: нужен отдельный
  предрегистрированный прогон и пересчёт затронутых артефактов.

**Найденный дефект тестовой инфраструктуры (важно):** JUnit 5 не исполняет тест-метод,
возвращающий не-`Unit`. В проекте было **90 таких методов** (`fun x() = runBlocking { … Mockito.verify(...) }`
или `= assertThrows(...)`), которые **молча не запускались**: 17 классов, 41 тест числился
«зелёным», ни разу не выполнившись. Все переведены на `(): Unit =`, после чего вскрылись
и исправлены реальные дефекты самих тестов:

- `Mockito.eq/any/argThat` для non-null параметров Kotlin → NPE (`AutoStopEventListenerTest`,
  `RoutedOrderTransportTest`, `LlmSignalStrategyTest`, `MoexFundingHistoryLoaderTest`,
  `CbrRatesHistoryLoaderTest`) — заменены helper-паттерном из AGENTS;
- `verify()` на suspend-функции с non-null возвратом (`saveAll`) → NPE — заменено на
  захват аргумента через `thenAnswer`;
- пропущенный 7-й аргумент (`purpose`) в `verify(placeLimit(...))` → «7 matchers expected, 6 recorded»;
- невалидный JSON в тесте пагинации (`"data": <rows>` без внешних скобок) — падал первый же парс;
- `assertFailsWith` вокруг `async`: сбой дочерней корутины отменял `runBlocking` до `await` —
  обёрнуто в `supervisorScope`;
- 2 теста ожидали немедленного обнуления `slOrderId/tpOrderId` у закрытой позиции, хотя
