# SETUP_GUIDE.md — Как установить робота с нуля

> **Для не-айтишника это означает, что:** этот документ — пошаговый рецепт. Вы идёте по нему, как по кулинарной книге: выполнили пункт — поставили галочку — перешли к следующему. Если что-то пошло не так — загляните в [TROUBLESHOOTING.md](TROUBLESHOOTING.md), там разобраны самые частые ошибки.

---

## 0. Что мы делаем и в каком порядке

Наш робот — это программа, которая сама торгует на бирже. Чтобы она заработала, нужно:

| Шаг | Что делаем | Сколько времени |
|---|---|---|
| 1 | Скачиваем код робота с GitHub | 1–2 мин |
| 2 | Ставим Docker Desktop (программу, которая запускает «коробки»-контейнеры) | 10–20 мин |
| 3 | Создаём файл `.env` (в нём живут ваши секретные ключи) | 15 мин |
| 4 | Запускаем робота | 2 мин |
| 5 | Проверяем, что всё работает | 2 мин |

**Важно знать заранее:** робот написан на Java (Kotlin), а не на Python. Поэтому вместо «виртуального окружения» (venv) здесь используется **Docker** — то же самое по духу, только надёжнее (объясняем в разделе 2). Никакие библиотеки вручную ставить не нужно — всё скачается само.

## 1. Как скачать код с GitHub

Сначала найдите репозиторий проекта на GitHub (у вас должна быть ссылка на него).

**Для не-айтишника это означает, что:** GitHub — это «облачная библиотека», где хранится код. Ваша задача — скопировать книгу (код) с полки (GitHub) к себе на компьютер. Сделать это можно двумя способами.

### Способ А. Простое скачивание архивом (для первого раза, без установки Git)

1. Откройте страницу репозитория на GitHub.
2. Нажмите зелёную кнопку **Code** (справа вверху над списком файлов).
3. В выпадающем меню нажмите **Download ZIP**.
4. Компьютер скачает файл `trading-bot-main.zip`.
5. Распакуйте архив (правой кнопкой → «Извлечь всё…») в удобную папку, например `C:\Users\<Ваше_имя>\trading-bot`.

**Минус способа А:** когда автор обновит робота, вам придётся скачивать архив заново и снова распаковывать. Обновляться «по кнопке» не получится.

### Способ Б. Клонирование через Git (рекомендуется)

Git — это программа, которая скачивает копию кода и позволяет потом получать обновления одной командой.

1. Установите Git: https://git-scm.com/download/win (жмите «Next» до конца, ничего менять не надо).
2. Откройте **PowerShell**:
   - нажмите кнопку «Пуск» (Windows);
   - начните печатать `PowerShell`;
   - нажмите Enter.
3. Перейдите в папку, где будет жить робот, например:
   ```powershell
   cd C:\Users\<Ваше_имя>
   ```
4. Скопируйте код одной командой (адрес репозитория возьмите с GitHub: кнопка **Code** → вкладка **HTTPS**):
   ```powershell
   git clone https://github.com/<ваш-логин>/trading-bot.git
   ```
5. Зайдите в скачанную папку:
   ```powershell
   cd trading-bot
   ```

**Чем отличается А от Б (простыми словами):** способ А — это как ксерокопия книги: вы держите в руках бумагу, но обновления вам не придут. Способ Б — это как подписка на журнал: когда выйдет новый номер, достаточно одной команды `git pull`, чтобы получить его.

Как получать обновления (работает только в способе Б):
```powershell
cd C:\Users\<Ваше_имя>\trading-bot
git pull
```

> Если у вас Windows и Git ставился со всеми настройками по умолчанию, команда `git` будет работать прямо в PowerShell после перезапуска окна.

## 2. Как установить Docker Desktop (главная программа)

**Для не-айтишника это означает, что:** роботу для работы нужны ещё несколько вспомогательных программ — база данных (как склад, где хранятся сделки) и кэш (как блокнот для быстрых записей). Устанавливать их по отдельности сложно и опасно: они могут «поссориться» с другими программами на вашем компьютере.

**Docker решает эту проблему.** Представьте, что каждая программа живёт в своей отдельной герметичной коробке-контейнере: в одной коробке база данных, в другой — кэш, в третьей — сам робот. Коробки не мешают друг другу и не трогают ничего за пределами своего пространства. Когда коробка больше не нужна — вы её выбрасываете, и на компьютере не остаётся мусора.

Если вспомнить аналогию с Python: виртуальное окружение `venv` — это «песочница для библиотек одной программы». Docker — это «песочница для целых программ со всем их содержимым». Для Java-проекта нужен именно Docker.

### Шаг за шагом

1. Скачайте установщик: https://www.docker.com/products/docker-desktop/ → кнопка **Download for Windows**.
2. Запустите скачанный файл и нажимайте «Next» / «Install».
   - Если система спросит про **WSL 2** — соглашайтесь, это нормально (Docker использует встроенную в Windows подсистему Linux).
   - Возможно, потребуется **перезагрузка компьютера** — сделайте это.
3. После установки запустите **Docker Desktop** (ярлык на рабочем столе). В первый раз он попросит принять условия — принимайте.
4. Дождитесь, пока внизу слева загорится зелёная надпись **Engine running**. Это значит, что Docker готов.

Проверка, что Docker работает, в PowerShell:
```powershell
docker version
```
Если вы видите текст с номерами версий — всё в порядке.

> **Первый запуск долгий.** Когда вы впервые запустите робота, Docker будет скачивать с интернета «коробки» (образы). Это нормально и происходит один раз. Не выключайте интернет и подождите.

## 3. Что нужно знать о ключах, прежде чем заполнять `.env`

**Для не-айтишника это означает, что:** у робота три «двери», для каждой нужен свой ключ:

1. **Дверь к брокеру Алор** — чтобы робот мог видеть котировки и отдавать приказы на биржу (в режиме LIVE) или получать виртуальные данные (в режиме SIMULATION).
2. **Дверь к искусственному интеллекту (LLM)** — робот спрашивает у ИИ совета, какие стратегии придумать.
3. **Дверь на ваш компьютер** — логин и пароль для входа в веб-интерфейс робота.

### Что такое API-ключ

API-ключ — это **строка символов, которая работает как пропуск-пароль для программы**. Когда робот обращается к сервису (например, к брокеру), он показывает этот пропуск, и сервис понимает: «Это тот самый пользователь, я знаю, какой у него счёт».

Пример ключа: `eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0...`

Ключ похож на пароль, но есть два отличия:
- ключ выдаётся **под конкретную программу** (не для человека, а для робота);
- по ключу сервис понимает, **какие действия разрешены** (например, только читать котировки или ещё и торговать).

> **Золотое правило:** ключ — это как ключ от квартиры. Вы не вешаете его на дверь подъезда и не публикуете в соцсетях. Если кто-то получит ваш ключ, он сможет распоряжаться вашим счётом. Подробнее — в разделе 5 («как не слить ключи»).

### Где взять ключи брокера Алор (этот робот торгует через Алор)

**Для не-айтишника это означает, что:** Алор — это российский брокер, через которого робот выходит на Московскую биржу. Чтобы получить ключи, нужен счёт в Алоре.

1. Зарегистрируйте счёт в Алоре: https://www.alor.ru (нужен паспорт и телефон, обычно 1–2 дня на открытие счёта).
2. Войдите в личный кабинет клиента Алора.
3. Найдите раздел **«Разработчикам» / «API» / «Ключи разработчика»** (у Алора есть отдельный портал для разработчиков: https://alor.dev — точное расположение кнопок может меняться, ищите слова «API» или «Ключи разработчика»).
4. Создайте **API-ключ разработчика**. Вам понадобятся три вещи:
   - **`ALOR_TOKEN`** — «пропуск» для робота (access token), длинная строка вида `eyJ...`;
   - **`ALOR_REFRESH_TOKEN`** — «запасной пропуск»: когда основной пропуск истекает (примерно через час), робот автоматически получает новый по запасному. Без него робот через час «закроет дверь»;
   - **`ALOR_PORTFOLIO`** — номер вашего счёта-портфеля у брокера, обычно строка вида `D12345`. Он есть в личном кабинете, в настройках счёта («Внешний счёт» / «Номер портфеля»).
5. Скопируйте все три значения в безопасное место — они понадобятся в разделе 4.

> **Важно:** на этапе симуляции (режим `SIMULATION`) ключи Алора формально не обязательны — робот сам выдумывает цены. Но без них вы не сможете протестировать переход в реальную торговлю, поэтому лучше получить их заранее.

### Где взять ключ для ИИ (LLM)

Роботу нужен доступ к «мозгу» — нейросети. По умолчанию это **RouterAI** (агрегатор, сам выбирает лучшую модель). Альтернативы: Kimi, DeepSeek, Qwen.

| Сервис | Где получить ключ | Переменная |
|---|---|---|
| RouterAI (по умолчанию) | https://routerai.ru → регистрация → «API-ключ» | `LLM_API_KEY` |
| Kimi | https://platform.moonshot.ai → «API Keys» | `KIMI_API_KEY` |
| DeepSeek | https://platform.deepseek.com → «API Keys» | `DEEPSEEK_API_KEY` |
| Qwen | https://dashscope.console.aliyun.com → «API-KEY» | `QWEN_API_KEY` |

> **Совет новичку:** начните с RouterAI — там один ключ на всё. Большинство сервисов дают небольшой бесплатный баланс для тестов, но за серьёзное использование обычно надо платить (у RouterAI — пополнение через сайт). Без ключа ИИ робот тоже работает, но «думает» примитивнее — использует запасные варианты.

### Пароли для входа в веб-интерфейс

Это не внешние ключи, а просто ваши пароли:
- **`AUTH_USER`** / **`AUTH_PASSWORD`** — администратор (может менять настройки, включать/выключать торговлю).
- **`ANALYTICS_USER`** / **`ANALYTICS_PASSWORD`** — аналитик (только смотрит, ничего не меняет). Можно не заполнять на первых порах.
- **`JWT_SECRET`** — секретная фраза, которой робот «подписывает» ваши сессии входа, чтобы никто не подделал их. Это аналог печати на документе. Сгенерируйте случайную строку (команды ниже).

## 4. Как заполнить файл `.env`

**Для не-айтишника это означает, что:** `.env` — это «карточка настроек» робота: список «имя = значение», где живут все ключи и важные параметры. Файл лежит в папке проекта, а Docker сам читает его при запуске.

> **Файл называется ровно `.env`** — без имени перед точкой. Windows может «возмутиться», что у файла нет имени — это нормально, соглашайтесь на создание. Не меняйте имя!

### Шаг 1. Создайте файл `.env`

В PowerShell, находясь в папке проекта:
```powershell
cd C:\Users\<Ваше_имя>\trading-bot
New-Item -ItemType File -Name .env
```

### Шаг 2. Откройте его в Блокноте

```powershell
notepad .env
```

### Шаг 3. Вставьте готовый шаблон

Скопируйте текст ниже в Блокнот и замените значения в угловых скобках `<...>` на свои:

```dotenv
# ==================== БАЗА ДАННЫХ (заполняется обязательно) ====================
# Пароль для внутренней базы данных робота. Придумайте любой надёжный, например: Tr3@ture!2026
DB_PASS=<придумайте-надёжный-пароль>

# ==================== БРОКЕР АЛОР (для SIMULATION можно оставить пустым) ========
ALOR_TOKEN=
ALOR_REFRESH_TOKEN=
ALOR_PORTFOLIO=D12345

# ==================== ИСКУССТВЕННЫЙ ИНТЕЛЛЕКТ ====================
# Провайдер: ROUTER_AI (по умолчанию), KIMI, DEEPSEEK или QWEN
LLM_PROVIDER=ROUTER_AI
LLM_API_KEY=<ваш-ключ-routerai>
# Если выбрали Kimi, раскомментируйте и заполните:
# KIMI_API_KEY=<ваш-ключ-kimi>

# ==================== ТОРГОВЛЯ ====================
# SIMULATION = виртуальные деньги (БЕЗОПАСНО). LIVE = реальные деньги (ОПАСНО!)
TRADING_MODE=SIMULATION
# Сколько новых позиций робот может открыть за один цикл. 0 = не открывать вообще.
# Для симуляции ставьте 1, для прод — начинайте с 0 и наблюдайте.
MAX_OPEN_POS=1

# ==================== ВЕБ-ИНТЕРФЕЙС ====================
# Администратор (обязательно, без этого робот не запустится)
AUTH_USER=admin
AUTH_PASSWORD=<придумайте-надёжный-пароль>
# Аналитик (можно оставить пустым)
ANALYTICS_USER=
ANALYTICS_PASSWORD=

# Секретная подпись сессий. Обязательно, минимум 32 символа. Используйте команду ниже.
JWT_SECRET=<вставьте-сгенерированную-строку>

# Токен для мониторинга Prometheus (можно сгенерировать той же командой)
METRICS_SCRAPE_TOKEN=<вставьте-сгенерированную-строку>
```

### Шаг 4. Сгенерируйте случайные строки для `JWT_SECRET` и `METRICS_SCRAPE_TOKEN`

Проще всего доверить случайность компьютеру. В PowerShell:

```powershell
# Сгенерировать 48 случайных байт и превратить их в текст
$bytes = New-Object byte[] 48
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

Выполните эту команду **дважды** — получите два разных набора символов: первый вставьте вместо `<вставьте-сгенерированную-строку>` в `JWT_SECRET`, второй — в `METRICS_SCRAPE_TOKEN`.

> Если вы на Linux / Mac (или в облачной машине), та же команда в bash:
> ```bash
> openssl rand -base64 48
> ```

### Шаг 5. Сохраните файл и закройте Блокнот

В Блокноте: «Файл» → «Сохранить» (Ctrl+S). Готово — карточка настроек заполнена.

## 5. Как не «слить» ключи в интернет случайно

**Для не-айтишника это означает, что:** когда код лежит в GitHub, мир может его прочитать. Если вместе с кодом «уедет» файл `.env`, то вместе с ним «уедут» и ваши ключи от счёта. Ниже — правила, которые делают это невозможным.

1. **Проверьте, что `.env` игнорируется git.** В папке проекта есть файл `.gitignore` — это «чёрный список» для git. В нём уже есть строки:
   ```
   .env
   .env.*
   ```
   Это значит, что git не следит за `.env` и никогда не предложит его «закоммитить». Проверить можно командой:
   ```powershell
   git status
   ```
   Если в списке изменённых файлов **нет** `.env` — всё в порядке.
2. **Не вставляйте ключи в чаты, скриншоты и общие документы.** Скриншот файла `.env` — это как фото ключа от квартиры.
3. **Не называйте ключи «в лоб».** Не создавайте файлы типа `my_keys.txt`, `secrets.txt` — они легко попадают в поисковики. Оставьте всё в `.env`.
4. **Если ключ всё же утёк** — срочно перевыпустите его в кабинете брокера/LLM-сервиса (там есть кнопка «Сбросить ключ» / «Создать новый»). Старый ключ перестанет работать.
5. **Не выкладывайте логи.** В логах может встретиться информация о позициях и ценах (но не ключи — робот их не печатает). Если просите помощи на форуме, вырезайте личное.
6. **Держите `.env` только там, где это нужно:** на своём компьютере и на облачной машине (см. DEPLOYMENT.md), но не в GitHub.

## 6. Запуск робота в первый раз

**Для не-айтишника это означает, что:** теперь мы собираем все «коробки» вместе и включаем. Одна команда поднимает и базу данных, и кэш, и самого робота, и веб-интерфейс.

1. Убедитесь, что Docker Desktop запущен (зелёный индикатор).
2. В PowerShell перейдите в папку проекта:
   ```powershell
   cd C:\Users\<Ваше_имя>\trading-bot
   ```
3. Запустите всё одной командой:
   ```powershell
   docker compose up -d
   ```
   - `up` — запустить сервисы;
   - `-d` (detach, «отдельно») — работать в фоне, чтобы окно PowerShell не блокировалось.
4. Первый запуск долгий (Docker скачивает образы и собирает робота). Следите за прогрессом — можно открыть второе окно PowerShell и смотреть статус:
   ```powershell
   docker compose ps
   ```
   Когда колонка `STATUS` у всех сервисов станет `running` (или `healthy`) — всё поднялось.

Полезные команды на будущее:

```powershell
# Посмотреть, что пишет робот в лог (нажмите Ctrl+C, чтобы выйти из просмотра)
docker compose logs -f app

# Остановить всё
docker compose down

# Перезапустить робота (если меняли .env)
docker compose up -d --force-recreate
```

> **Если что-то упало** — не паникуйте. Большинство первых ошибок разобрано в [TROUBLESHOOTING.md](TROUBLESHOOTING.md) (нет интернета, занят порт, слабый пароль и т.д.).

## 7. Проверка, что робот жив

1. Проверьте «пульс» робота. В PowerShell:
   ```powershell
   curl.exe http://localhost:8080/actuator/health
   ```
   Ожидаемый ответ (примерно):
   ```json
   {"status":"UP"}
   ```
   `UP` значит «жив и здоров». Если `DOWN` — смотрите логи (`docker compose logs app`).

2. Откройте веб-интерфейс в браузере: **http://localhost** и войдите под логином `AUTH_USER` и паролем `AUTH_PASSWORD` из `.env`.

3. Проверьте, что робот работает в безопасном режиме. В логах (`docker compose logs app`) при старте должно быть:
   ```
   TRADING_MODE=SIMULATION, MAX_OPEN_POS=...
   ```
   Режим `SIMULATION` = виртуальные деньги.

## 8. Как правильно останавливать и обновлять робота

**Останавливаем:**
```powershell
docker compose down
```
Робот завершится аккуратно. База данных и накопленная статистика сохраняются в «дисках» Docker (volumes) — при следующем запуске всё будет на месте.

**Обновляем до новой версии (если клонировали через git):**
```powershell
cd C:\Users\<Ваше_имя>\trading-bot
git pull
docker compose up -d --build
```
`--build` пересоберёт робота из новых исходников. `.env` при этом не трогается — ваши ключи сохранятся.

> **Совет:** перед обновлением смотрите, что изменилось: `git pull` сам покажет список изменённых файлов. Иногда меняются обязательные переменные `.env` — если робот после обновления не стартует, свежие требования ищите в разделе 8 документа CONFIGURATION.md.
