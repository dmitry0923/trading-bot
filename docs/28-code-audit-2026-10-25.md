## 4. Что это значит для текущих результатов

- P0 №7/№8 относятся к **live/SIM исполнению**, не к research: после фикса
  неисполненный лимитный вход больше не становится «открытой позицией», а pending
  вход связывается с outbox и разрешается реконсилятором.
- P1 №6 меняет сайзинг акций только там, где SL отличается от 2% (сетка
  `stockGrid`); результаты с SL=2% не изменились.
- P2 №5 меняет комиссию только при **дробном** `commissionMultiplier`
  (стресс-прогоны MC с 2/3/5 не затронуты).
- Дефекты §2 (особенно №10, №12, №13) — это ограничения **сопоставимости**
  уже опубликованных бэктестов. Их нельзя править молча: нужен отдельный
  предрегистрированный прогон и пересчёт затронутых артефактов.

### 5.4 Правило измерения

- В покрытие входит `test` + `integrationTest` (Kover агрегирует оба).
- Из знаменателя не исключаются «неудобные» пакеты — иначе цифра перестаёт

  оформляется отдельным правилом Kover и явно документируется.

## 6. Приоритет следующей итерации (не сделано в этой)

1. **SIM-исполнение (P0, docs/28 §3 №32):** в `TRADING_MODE=SIMULATION`
   `verifyOrder` всегда `null` → входы остаются `pendingEntry`. Нужен явный
   SIM-fill (цена заявки, qty) + тест; после этого SIM начнёт реально торговать,
   поэтому включать осознанно (текущий пилот не перезапускался).
2. **WS-контракт (P1):** приоритет `orderNumber` над `id` (§3 №19), убрать `break`
   после `Last` (§3 №20), подтвердить на живом payload.
3. **Время и outbox (P1):** единый `Clock`/TZ для `closed_at`/`opened_at` (§3 №23),
   инкремент `retry_count` при reclaim PROCESSING (§3 №21), убрать смешение
   JVM-времени и `now()` БД (§3 №22), `lastPrice=0` → `null` (§3 №24).
4. **Research-семантика (§2):** отдельный предрегистрированный прогон с флагом
   `entry-bar-exit-check`, исправлением equity-кривой и `BacktestRiskSimulator`;
   пересчёт затронутых артефактов. Без этого сравнивать новые результаты со
   старыми нельзя.
5. **Покрытие:** фазы §5.3 (≈205 тестов, 2–3 дня) до глобальных 90 %.
